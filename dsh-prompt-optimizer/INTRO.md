# dsh-prompt-optimizer ·「优化提示词」

> 在输入框工具条注入一个「优化提示词」按钮：读取你正在写的草稿，按统一标准重写成
> 结构完整、目标明确、可直接执行的提示词，然后一键回填 —— 全程不离开输入框。

## 它解决什么问题

写提示词时最常见的四个损耗：

1. **懒得写全** —— 只写「写个登录页」，模型只能猜，猜错就得来回好几轮。
2. **切窗口的代价** —— 想优化一下就得开另一个对话、复制粘贴、再切回来。
3. **优化结果不可控** —— 通用改写工具会"顺手"替你补上你没说过的技术栈、版本、依赖。
4. **改完不知道改了什么** —— 拿到一版新提示词，却不知道它动了哪里、为什么。

这个插件把这件事收敛成**输入框旁边的一次点击**，并且明确区分"补结构"和"编事实"。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| **就地优化** | 按钮在输入框工具条（`conversation.input.right`），面板在输入框正上方（`conversation.input.dock`），不打断你的输入流程 |
| **统一标准** | 8 条优化原则 + 九段骨架 + 三段式输出，模型路径与本地引擎**同一套标准** |
| **双引擎** | 优先走你的默认模型（语义理解好）；失败自动回落本地规则引擎（离线、零延迟、零成本） |
| **四个动作** | 替换原文 / 追加到末尾 / 复制 / 撤销，另有优化后 · 原文 · 对比三个视图 |
| **保真** | 代码块、行内代码、变量与函数名、命令、文件路径、URL、报错信息、数学公式**逐字保留**，不翻译不改写 |
| **不编造** | 技术栈、版本号、路径、数值一律不写入。信息不足时写「（原文未提供，未作假设；如信息不足请先提问。）」，只标注、不假设 |
| **中英双语** | 中文进中文出、英文进英文出；界面词典随宿主语言切换 |
| **可调** | `mode` / `temperature` / `maxTokens` / `reasoningEffort` / 超时 / 失败熔断 / 严格保真 |

## 优化标准

### 优化原则

1. 保留用户原始意图，不改变核心需求。
2. 不编造用户没有提供的事实、数据或背景。
3. 自动补全必要结构。其中「角色 / 步骤 / 输出格式 / 验收标准」是**结构性**内容，可给通用默认；
   「背景 / 要求 / 约束」是**事实依赖**内容，原文没给就只标注。
4. 原文太短可合理扩展，但必须保持原意。
5. 代码、变量、专有名词、URL、公式必须原样保留。
6. 信息不足不胡乱假设 —— 写成「如信息不足，请先提问」或显式标注。
7. 中英文均支持，默认与原文同语言输出。
8. 输出要具体、可执行、少歧义，适合直接交给大模型。

### 输出格式（严格三段）

```
## 优化后的提示词
（提示词本体，用三级标题分节）

## 主要优化点
- 按标准九段骨架重组：原文内容已归入 7 段（角色、目标、任务、约束、步骤、输出格式、验收标准）。
- 自动补全必要结构：角色、任务、步骤、输出格式 —— 只补结构与预期，未新增任何事实。
- 标注 2 处原文未提供的信息（背景、要求），未作假设。
- 篇幅：原文 51 字 → 优化后 363 字。

## 使用建议
- 把上面「优化后的提示词」整段复制给大模型即可。
- 其中 背景、要求 标注了「原文未提供」：若这些信息影响结果，请先补上。
```

### 一个真实样例

输入：

```
帮我写一个 Python 脚本，读取 CSV 并统计每列缺失率。不要用 pandas。验收标准：能跑通 10 万行。
```

输出（节选）：

```markdown
## 优化后的提示词

### 角色
你是该领域的资深专家，熟悉这类任务的常见做法、边界条件与失败模式，并能主动指出需求中的歧义与风险。

### 目标
帮我写一个 Python 脚本，读取 CSV 并统计每列缺失率。

### 背景
（原文未提供，未作假设；如信息不足请先提问。）

### 约束
不要用 pandas。

### 验收标准
能跑通 10 万行。
```

注意几件事：`Python`、`pandas`、`10 万行` 都原样保留；「验收标准：」这个标签被剥掉了（标题已经说明）；
「背景」没有编一段业务场景，而是明确标注待补。

## 双引擎与回落策略

```
点击按钮
   │
   ├─ mode=auto（默认）──→ 有默认模型？──→ 调模型（可用时优先）
   │                            │
   │                            └─ 失败 → 记一次失败，回落本地规则引擎
   │                                      连续失败 3 次后本进程内直接走本地
   │
   ├─ mode=model ──→ 只用模型，失败即报错（不静默降级）
   └─ mode=rules ──→ 纯本地规则引擎：不联网、零延迟、零成本
```

**本地规则引擎不是"降级残废版"**：它执行同一套九段骨架标准，同样保真、同样不编造。
它的短板只在**归类**——靠关键词把句子分到九段里，语义理解不如模型。

**回落时不会白点**：你依然拿到结果，并且「主要优化点」里会写明为什么回落的。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖：

```yaml
- id: 'dsh-prompt-optimizer'
  name: 'dsh-prompt-optimizer'
  config:
    mode: auto                # auto | model | rules
    temperature: 0.3
    maxTokens: 8192
    reasoningEffort: auto     # auto | minimal | low | medium | high | max
    retryOnMaxTokens: true
    timeoutMs: 60000
    failureCircuitThreshold: 3
    strictPreservation: false
```

| 配置项 | 默认 | 含义 |
| --- | --- | --- |
| `mode` | `auto` | 有模型就用模型、失败回落规则；`model` 只走模型；`rules` 纯离线 |
| `temperature` | `0.3` | 改写任务建议偏低，避免自由发挥 |
| `maxTokens` | `8192` | 单次输出上限。**推理模型的思考 token 也计入这个上限** |
| `reasoningEffort` | `auto` | 自动挑该模型支持的**最低**一档；模型不报能力就不传（不支持的显式强度会被服务端直接拒绝） |
| `retryOnMaxTokens` | `true` | 撞到输出上限时翻倍重试一次（封顶 32768） |
| `failureCircuitThreshold` | `3` | 连续失败到此次数后，本进程内直接走本地引擎 |
| `strictPreservation` | `false` | 追加更严格的保真约束（未提供的事实用 `<PLACEHOLDER: …>`） |

## 已知边界

- **不持久化**：优化结果只存在内存里，关掉页面即丢。不做历史记录。
- **不替你改需求**：它只把话说明白，不会把你的任务换成另一个任务。
- **本地引擎的归类靠关键词**，复杂句可能归错段；想要更准就用模型路径。
- **面板依赖两个插槽**（`conversation.input.right` / `conversation.input.dock`），
  针对 dsh 0.2.0-rc.2 验证；宿主大版本变动后需要重新核对插槽契约。
- **推理模型的 token 预算**：`maxTokens` 约束整次输出（含思考），
  极长的提示词仍可能撞上限 —— 插件会自动翻倍重试一次并给出可执行的建议。
- **未发布到 npm、未收录进市场目录**：所以市场「已安装」那一行没有目录简介
  （目录简介来自 awesome-dsh-plugin.com 的登记项）。可以在市场里给这一行写**自定义说明**
  （上限 200 字），把上面那个「一句话版本」粘进去即可。

## 技术实现

- **双半结构**：Host 半（`lib/index.js`）注册三条精确 HTTP 路由
  `/plugin-prompt-optimizer/{info,optimize,report}`；Client 半（`lib/client.js`）
  是一个**自包含经典脚本**，通过 `window.__ModuleLoader__.load({ id, factory })` 自注册，
  再向两个插槽注入按钮与面板。
- **同一份规则引擎**：`lib/rules.js` 被 Host 直接 `import`，同时由构建脚本
  按 `//#region rules` 标记**逐字内联**进客户端 bundle —— 两侧行为不可能漂移。
- **跨插槽共享状态**：按钮与面板是两个独立的 React 实例，`useState` 按实例隔离，
  所以状态放在组件之外、按 `sessionId` 共享，两侧用 `useSyncExternalStore` 订阅同一份快照。
- **零运行时依赖**：只用 Node 内置模块与宿主提供的 `react`。
- **配置永远不抛错**：非法值一律回落默认值，一个写错的配置项不该让插件在 loader 阶段挂掉。
- **HTTP 处理器永不 reject**：承载层需要错误正文，而不是一个空 500。
